# 便单数据模型与写入规则

本文面向第三方客户端开发者，依据便单鸿蒙端的建表和读写规则，说明四张核心同步表、全部 44 列以及跨表写入约定。字段名区分大小写。接入和授权步骤见 [从零接入便单云端数据与自动续期](cloud-access.md)。

| 表 | 列数 | 含义 | 关联 |
| --- | ---: | --- | --- |
| `favorites` | 3 | 待办单 | `id3` 被 `Task.id3` 引用。 |
| `Task` | 26 | 待办定义 | 一个 `id1` 可以对应多条执行实例。 |
| `showTask` | 9 | 待办执行实例 | `id1` 指向任务，`id2` 标识本次执行。 |
| `tomato` | 6 | 专注记录 | 可选的 `log.eventId` 指向 `showTask.id2`，没有独立外键列。 |

这些关系由业务代码维护。原生云空间同步配置包含四表。网页 HTTP 记录的外层 `id` 和 `version` 属于传输层，与表内业务主键和字段分开处理。云端业务 ID 由写入方分配，原生端由本地数据库自增。

### 类型、缺省与标识符

- 表中列出的类型是鸿蒙端存储类型。写入云端时，`TEXT` 使用 JSON 字符串，普通 `INTEGER` 使用整数，`REAL` 使用有限数值。读取业务 ID 时兼容数字或数字字符串，在客户端统一转为十进制字符串比较。`tomato.time` 的语义是毫秒时间戳。
- 除主键约束外，这四张表没有显式 `NOT NULL` 列约束。旧记录可能缺字段或含空值，读取时应容错。新记录按下表业务规则填齐所需字段。原生 SQL 的默认值只描述本地建表，云端写入应显式提供业务所需值，并通过读回确认。
- 云记录 `id` 用于定位请求，`version` 用于并发校验。`id1`、`id2`、`id3` 和 `time` 标识业务对象。云记录长 ID 始终按字符串保存。生成业务 ID 时使用 JavaScript 安全整数范围内的正整数；MCP 的范围上限为 `9007199254740991`，并在写入前检查冲突。重试同一笔创建要复用原业务 ID。
- 这里的日期和时刻对应设备或用户的本地日历。跨设备同步时保留原字段值。时区来自客户端设置，存储字段不带时区偏移。

| 表 | 原生 SQL 显式默认值 |
| --- | --- |
| `Task` | `unitTimeNumber=1`、`validStartTime="00:00:00"`、`validEndTime="23:59:59"`、`loopSet=0`、`duration=0` |
| `showTask` | `validStartTime="00:00:00"`、`validEndTime="23:59:59"`、`completedCount=0` |
| `favorites` | `favoritesColor=0` |
| `tomato` | `goodCount=0`、`badCount=0` |

## Task：待办定义

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `id1` | INTEGER | 任务主键。原生新建时自增，由数据库返回。 |
| `taskTitle` | TEXT | 待办标题。原生提交拒绝空字符串。 |
| `taskContent` | TEXT | 备注、子任务标题、附件引用的复合字段，见下节。 |
| `id3` | INTEGER | 所属待办单 `favorites.id3`。默认归到 `1`，原生模型将 `<= 1` 归一为 `1`。 |
| `isCollectible` | INTEGER | 收藏标志，`0` 否、`1` 是。 |
| `isImportant` | INTEGER | 重要标志，`0` 否、`1` 是。 |
| `isUrgency` | INTEGER | 紧急标志，`0` 否、`1` 是。和 `isImportant` 组成四象限。 |
| `startTime` | TEXT | 本地日期 `YYYY-MM-DD`。一次性任务的开始日，或重复系列的起始边界。 |
| `endTime` | TEXT | 本地日期 `YYYY-MM-DD`。一次性任务的结束日，或重复系列的结束边界。 |
| `isLoop` | INTEGER | `0` 一次性，`1` 普通重复，`2` 标记为习惯的重复任务。原生展示以 `>= 2` 判断习惯。 |
| `haveNoTime` | INTEGER | `1` 无指定时间，`0` 有指定时间。原生无时间任务仍保留日期和时段，默认范围是 1970-01-01 至 2100-12-31，有设置可将开始日改为当天。重复任务走有时间的路径。 |
| `unitTimeNumber` | INTEGER | 每个实例的完成要求。普通模式 `1–99` 表示目标次数，默认 `1`，原生模型把非正数归一为 `1`。`>= 100` 表示子任务目标位掩码乘 100。 |
| `validStartTime` | TEXT | 本地开始时刻，形如 `09:30:00`。与开始日配对，重复实例通常继承该值。建表默认 `00:00:00`。 |
| `validEndTime` | TEXT | 本地结束时刻，与结束日配对，重复实例通常继承该值。建表默认 `23:59:59`。原生表单格式化写入时秒位固定为 `00`。 |
| `loopSet` | INTEGER | `0` 仅一次、`1` 自定义、`2` 工作日、`3` 休息日、`4` 每天、`5` 艾宾浩斯、`6` 每周、`7` 每月、`8` 每年。 |
| `loopBaseNumber` | INTEGER | 自定义重复的间隔，填写正整数。每两周填 `2`，原生默认 `1`。 |
| `loopUnit` | INTEGER | 自定义重复的单位和工作日筛选选项。原生默认 `0`，编码见下节。 |
| `loopDate` | TEXT | 自定义重复选中的日期，编码由单位决定。原生默认空串。 |
| `duration` | INTEGER | 重复任务的单次实例持续天数。普通重复填至少 `1`，实例结束日为开始日加 `duration - 1`。每周、每月、每年预设按周期边界计算。一次性任务默认 `0`，用起止日表达跨度。 |
| `isRemind` | INTEGER | 位 0 表示时间提醒，位 1 表示地点提醒。`0` 全关、`1` 仅时间、`2` 仅地点、`3` 全开。单独修改一项时保留另一位。`isLocationRemind` 是应用模型属性，由这一列解码。 |
| `remindDate` | TEXT | 时间提醒的本地日期 `YYYY-MM-DD`。关闭后仍可能有值，是否启用看 `isRemind`。 |
| `remindTime` | TEXT | 时间提醒的本地时刻 `HH:mm:00`，与 `remindDate` 来自同一提醒时间。 |
| `isFinish` | INTEGER | 任务汇总状态，新建为 `0`。实例操作后的原生汇总路径中，只要还有 `isFinish = 0 AND completedCount >= 0` 的实例，任务即为未完成。已放弃实例不计入这个未完成数。 |
| `latitude` | REAL | 地点纬度。原生新建表单未设置时用 `-1`。 |
| `longitude` | REAL | 地点经度。原生新建表单未设置时用 `-1`。 |
| `location` | TEXT | 地点名称或显示文本，原生默认空串。启用地点提醒以 `isRemind` 的地点位为准。 |

日期和时刻按本地日历格式化，文本本身没有时区偏移。外部工具解析「今天」「明天下午」时应先确定用户时区，再生成日历日期和时刻。

### taskContent 编码

| 形态 | 写入示例 |
| --- | --- |
| 兼容旧纯文本 | `出门前确认` |
| 备注与子任务 | `JSON.stringify(["出门前确认", "带钥匙", "带证件"])` |
| 备注、附件与子任务 | `JSON.stringify([JSON.stringify(["出门前确认", ["file-id-1"]]), "带钥匙", "带证件"])` |

外层必须是字符串数组，首元素是备注或附件包，后续元素按位置对应子任务。附件包也是字符串，解码后形如 `[备注, 文件引用数组]`。只有首元素会按附件包解析。无法按合法结构解码的旧内容仍按纯文本显示。

改备注应先解码并保留子任务和附件引用。子任务标题与进度位按位置对应。调整子任务顺序或移除中间项时，要同时维护受影响实例的进度位和完成状态。

### loopUnit 和 loopDate 编码

`loopUnit = 单位 + 100 × 筛选类型`。筛选类型 `0` 不筛选、`1` 只保留休息日、`2` 只保留工作日。例如 `201` 表示按周，仅保留工作日。工作日和休息日判断受原生调休设置影响。

| 单位，即 `loopUnit % 100` | `loopDate` 填法 | 示例 |
| --- | --- | --- |
| `0` 天 | 留空，由间隔决定。 | `""` |
| `1` 周 | 逗号分隔，`0` 周日到 `6` 周六。 | `"1,3,5"` |
| `2` 公历月 | 逗号分隔的 `1–31` 日号，`32` 表示当月最后一天。 | `"1,15,32"` |
| `3` 公历年 | 逗号分隔的 `MM-DD`。 | `"06-06,12-25"` |
| `4` 农历月 | 逗号分隔的 `1–30` 日号。 | `"1,15"` |
| `5` 农历年 | 逗号分隔的农历月和日。 | `"01-01,08-15"` |

自定义重复除「按天」外要求 `loopDate` 非空。农历实例生成会尝试平月和闰月，再筛选有效日期。预设的每周、每月、每年对应以周、月、年为跨度的实例。比如「每周一」应用自定义按周并选星期一。

## showTask：执行实例

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `id2` | INTEGER | 实例主键。原生自增，完成当次和勾选当次子任务使用这个 ID。 |
| `id1` | INTEGER | 父任务 `Task.id1`。 |
| `startTime` | TEXT | 实例开始日 `YYYY-MM-DD`。一次性任务复制父任务，重复任务按规则生成。 |
| `endTime` | TEXT | 实例结束日 `YYYY-MM-DD`。一次性任务复制父任务，重复任务按持续天数或周期边界计算。 |
| `validStartTime` | TEXT | 本次开始时刻。实例生成时从父任务的时段派生。 |
| `validEndTime` | TEXT | 本次结束时刻。实例生成时从父任务的时段派生。 |
| `completedCount` | INTEGER | 初始 `0`，`-1` 表示放弃。普通模式是已完成次数，子任务模式是已勾选位掩码乘 `100`。模式由父任务 `unitTimeNumber` 确定。 |
| `recentFinishedTime` | TEXT | 最近记录进度的本地时间 `YYYY-MM-DD HH:mm:00`。一次性实例初始化为空串，重复实例初始化时可能预填生成时间。查询完成历史时需同时检查 `isFinish`。 |
| `isFinish` | INTEGER | 实例完成状态。初始 `0`，进度达到父任务要求后设为 `1`。更新或撤销后还要检查父任务汇总状态。 |

### 子任务目标和进度

第 `i` 个子任务对应位 `1 << i`，索引从 0 开始。连续的 `n` 个子任务初始目标为 `((1 << n) - 1) * 100`。例如三个子任务的目标为 `700`（二进制 `111` 乘 100），只勾第一项和第三项时进度为 `500`（二进制 `101` 乘 100），全勾时为 `700`。显示完成项数应统计置位数。原生编辑界面的普通目标上限为 99 次，子任务上限为 20 项。

## favorites：待办单

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `id3` | INTEGER | 待办单主键。原生自增，`1` 保留给默认分类。 |
| `favoritesName` | TEXT | 待办单名称。默认分类初始化名称为「默认」。 |
| `favoritesColor` | INTEGER | `排序索引 * 100 + 颜色索引`。读取先按原值升序排序，再以 `% 100` 提取颜色。原生色表 `0` 是默认色，`1–24` 为预设色。例如 `305` 表示排序索引 3、颜色 5。单独改颜色或顺序时保留另一部分。 |

### 色板索引

`0` 为默认色。下表列出其余索引，按原生界面的色系和顺序排列。显示时可以按客户端主题取对应色值，写入时使用同一个索引。

| 色系 | 红 | 橙 | 黄 | 绿 | 湖蓝 | 浅蓝 | 深蓝 | 紫 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 鲜亮 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| 柔和 | 9 | 10 | 11 | 12 | 13 | 14 | 15 | 16 |
| 莫兰迪 | 17 | 18 | 19 | 20 | 21 | 22 | 23 | 24 |

读取 `favoritesColor` 时用整数除法除以 100 得到排序索引，取模得到颜色。原值 `305` 改成莫兰迪蓝 `22` 后是 `322`；再将排序移到 2 后是 `222`。

## tomato：专注记录

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `time` | INTEGER | 主键。原生计时和补记使用开始时间的毫秒时间戳。相同 `time` 指向已有记录，原生写入按调用参数决定是否覆盖。 |
| `date` | TEXT | 按开始时间计算的本地日期 `YYYY-MM-DD`，原生按此列进行每日统计。 |
| `goodCount` | INTEGER | 好番茄数，填写非负整数，默认 `0`。 |
| `badCount` | INTEGER | 坏番茄数，填写非负整数，默认 `0`。原生手工补记时好、坏番茄数都可为 `0`。 |
| `minutes` | REAL | 专注分钟数。计时器可写小数，手工补记向下取整。原生新增入口拒绝小于 1 分钟的记录。 |
| `log` | TEXT | 兼容空串与旧文本。未关联事项的原生计时可写结束时间的 `Date.toString()`，关联事项或手工填标题时可写 JSON 字符串。 |

关联事项时，`log` 的 JSON 形如：

```json
{
  "eventId": 123,
  "eventTitle": "写方案",
  "eventType": 4,
  "endTime": "Thu Nov 19 2026 15:25:00 GMT+0800"
}
```

`eventId` 是执行实例 `showTask.id2`，`eventTitle` 是存储时的标题，`eventType` 是当时的待办单 ID，`endTime` 是结束时间的 `Date.toString()` 文本。手工补记有自填标题时，`eventId` 和 `eventType` 都可为 `-1`。关联实例不存在时，保留专注记录，仍可按日期统计。

## 对外工具的写入约定

- 新建和修改日期时同时考虑任务定义和实例。原生一次性任务有一个实例，重复任务按重复规则生成实例。编辑当次、编辑系列是不同的业务操作。
- 完成、撤销、放弃及勾选子任务时维护实例进度、完成状态和父任务汇总。完成历史以实例状态和实际记录的时间为准。
- 删除任务时处理关联实例和附件生命周期。原生删除待办单区分「同时删除任务」和「将任务移回未分类」。
- 局部修改先解码已有数据，保留同字段里的其他内容。对外工具可以使用 `remark`、`subtasks`、`colorIndex`、`sortIndex` 等可读属性，再在写入时编码。云端的属性合并、版本冲突和多端同步需要按实际 HTTP 接口验证。

## 写入示例

以下例子展示保存到华为同步服务的两个 `attributes` 对象。示例业务 ID 需替换成当前账号中未占用的值。

### 新建一次性任务和对应实例

创建一条 2030-06-03 09:30–10:00 的任务，放入默认待办单，包含两个子任务和一个时间提醒。两个子任务都要完成，因此目标值为 `300`。

```json
{
  "id1": "1800000000000001", "taskTitle": "交材料",
  "taskContent": "[\"出门前确认\",\"带钥匙\",\"带证件\"]", "id3": "1",
  "isCollectible": 0, "isImportant": 0, "isUrgency": 0,
  "startTime": "2030-06-03", "endTime": "2030-06-03",
  "isLoop": 0, "haveNoTime": 0, "unitTimeNumber": 300,
  "validStartTime": "09:30:00", "validEndTime": "10:00:00",
  "loopSet": 0, "loopBaseNumber": 1, "loopUnit": 0, "loopDate": "", "duration": 0,
  "isRemind": 1, "remindDate": "2030-06-03", "remindTime": "09:00:00",
  "isFinish": 0, "latitude": -1, "longitude": -1, "location": ""
}
```

```json
{
  "id2": "1800000000000001", "id1": "1800000000000001",
  "startTime": "2030-06-03", "endTime": "2030-06-03",
  "validStartTime": "09:30:00", "validEndTime": "10:00:00",
  "completedCount": 0, "recentFinishedTime": "", "isFinish": 0
}
```

示例沿用 MCP 对一次性任务的 ID 分配方式。读已有记录时始终以 `showTask.id1` 关联任务。勾第一项后实例进度为 `100`，状态仍为 `0`。两项完成后进度为 `300`、实例状态为 `1`，同时记录实际完成时间并重算父任务汇总。

### 循环与地点提醒

- 每周一、周三各执行一次，自定义字段为 `isLoop=1`、`loopSet=1`、`loopBaseNumber=1`、`loopUnit=1`、`loopDate="1,3"`、`duration=1`。设为习惯时用 `isLoop=2`。为日期范围内每个命中日期生成一条实例。周一编码固定为 `1`，即便客户端选择周一作为一周起点。
- 保留时间提醒，增加地点提醒时，将 `isRemind` 从 `1` 改为 `3`，填写地点文本和成对的 GCJ-02 经纬度。纬度范围 `[-90, 90]`，经度范围 `[-180, 180]`。清除地点时可将坐标恢复为 `-1, -1`，并只清除地点提醒位。是否实际触发由启用了地点权限和提醒的终端决定。

### 检查跨端一致性

先读回已写入的 `Task` 和 `showTask`，核对业务 ID、日期、提醒位和子任务进度。再从另一个便单客户端按对应日期查看。如果一次操作只成功写入了一部分，按已写入的业务 ID 找到目标，再补齐缺失记录。
